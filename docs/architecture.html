Architecture

httpjet is a Cargo workspace: one binary crate (httpjet) over fourteen hj-* library crates. The graph is acyclic, with hj-config at the root and hj-core as the seam every handler programs against. More than 1,300 test functions span the 15 crates.

Workspace shape

Responsibilities are split so the contract a handler depends on (hj-core) is small and frozen, while transports, protocols, and the cache evolve independently behind it. Three libraries are deliberately isolated from the rest — they take no hj-* dependencies so their logic stays portable.

Crate dependency graph

hj-config resolves strict native TOML or LiteSpeed XML compatibility input into one normalized model; hj-core re-exports it so every downstream crate imports the configuration model through core. The binary is the only crate that sees everything.

Transport paths

The pure io_uring transport is now the only serving transport. There is no runtime --io-uring switch and no URING=0 rollback mode; reverting transport strategy is a rebuild from an older revision, not a CLI flag.

The binary's uring/ module runs one monoio runtime per inherited or self-bound SO_REUSEPORT listener. HTTP/1.1 uses a custom monoio + httparse codec; HTTP/2 and h2c route into native hj-h2; TLS terminates through monoio-rustls; HTTP/3 is uring/h3.rs, a quinn-proto driver using quinn-udp over io_uring UDP. Each path bridges into the same pipeline::handle(), so rewrite, LSAPI, proxying, page cache, telemetry, and reload state are shared regardless of wire protocol.

The frozen contract — hj-core

This is the seam that lets handlers compose without knowing the transport. Changing these signatures means updating every dependent, so they are treated as frozen:

hj-core · the seam
enum Body { Empty, Full(Bytes), Stream(BoxBody), File(FileBody) }
type Request  = http::Request<IncomingBody>;
type Response = http::Response<Body>;

// every terminal handler implements this
trait Handler { async fn handle(&self, &mut ReqCtx, Request) -> Result<Response, HandlerError>; }

// every post-handler munger implements this
trait ResponseTransform { async fn transform(&self, &ReqCtx, &mut Response); }

ReqCtx carries the per-request state: the server/vhost config (as Arcs), peer_ip/client_ip (post-XFF), is_tls, protocol, trusted_proxy, and an env vec (rewrite [E=] sets and CGI overrides). Router::resolve(listener, key) maps SNI/Host to a vhost.

i
Why it's frozen

New terminal handlers impl Handler and register in the pipeline's dispatch(); new response munging impl ResponseTransform and is pushed into the transform list. Neither requires touching handle() — that's the whole point of keeping the seam small.

The request pipeline

The binary's pipeline::handle() is the integration point. It resolves the vhost, enforces the mTLS trust boundary and ACL/real-IP, calls dispatch(), applies the response transforms, and writes the access log. dispatch() mirrors OpenLiteSpeed's ordering exactly:

resolveSNI/Host → vhost aclmTLS · real-IP · deny rewriteinline + .htaccess cachelookup (short-circuits) dispatchws · proxy · php · static finalizeheaders · error docs storecache write

The terminals are intentionally not a uniform matcher registry: their predicates (request headers vs path vs script-path split), fall-through rules, and post-processing all differ, so an explicit if/return chain keeps the security-relevant ordering legible. Two fall-throughs matter: a proxy context that can't resolve its ext-processor falls through to static, while a script with no PHP pool hard-fails 503 and must never fall through — a source-disclosure guard.

!
Load-bearing detail

A rewrite to index.php keeps the original REQUEST_URI (the resolved SCRIPT_FILENAME is pinned separately, with SCRIPT_NAME/QUERY_STRING pushed into ctx.env). That is what makes XenForo-style front-controller routing correct — and it is also why the page cache must key by the original URI, never the rewrite-resolved path.

The page-cache seams are inert unless runtime.page_cache.enabled is true (or the XML compatibility flag enables them): the lookup runs after rewrite/ACL resolve the path and env but before any backend, and the store runs after each terminal return. See the page cache for the full picture.
