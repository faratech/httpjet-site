Security & access control

Everything that decides who may ask and who the client is: the network ACL and trusted-proxy model, the opt-in per-client-IP throttle, geo/ASN rules served by the offline hj-geo source, PROXY protocol trust, Basic auth, TLS hardening, the fail-closed PHP jail, and the request limits enforced before any backend runs. The recurring design rule is fail closed: a control that cannot evaluate acts restrictive, never permissive.

resolve acl rewrite cache dispatch finalize store

Overview

Access control lives in hj-acl, fed by the <security> block of the XML config; geo/ASN membership comes from hj-geo; credentials from hj-rewrite's auth module; and transport-level identity from hj-tls and the PROXY-protocol gate. All of it runs in the resolve/acl stages — before rewrite, cache, and dispatch — so a rejected request never touches an application.

Network ACLs & client identity

Every decision that depends on "the client's IP" starts from the same resolved value, produced once at connection admission:

  • Direct peers are simply the socket address.
  • Trusted proxies: with useIpInProxyHeader at its default 2, an X-Forwarded-For chain is honored only when the immediate peer is in a trusted range (an allow rule with the T marker), and the Cloudflare CF-Connecting-IP header is recognized on that path. Levels 0–4 narrow or widen the trust: 0 never believes forwarded headers, 4 always does.
  • Unix-socket peers have no address — they see a fabricated loopback value, and the access log renders the literal host unix:.

On top of that identity: <accessControl> evaluates allow/deny CIDR rules most-specific-wins, with a trailing T on an allow rule marking a trusted proxy; <accessDenyDir> globs mark paths that are never served (a malformed glob is a hard start/reload error, not a warning); and <fileAccessControl> symlink policy treats owner-restricted mode (2) as fail-closed never-follow.

!
One spoofing rule

Forwarded-client headers are evidence, not identity. They count only from an explicitly trusted peer; from anyone else they are attacker-controlled data and are ignored.

Per-client-IP throttle

<tuning><perIpRate> caps requests per second per client IP over a fixed window (perIpRateWindowSecs, default 1 s); excess requests get 429. The implementation is a sharded fixed-window counter — 64 shards, capped at 4096 tracked IPs per shard — so the hot path is a couple of atomic increments and eviction is amortized, not a per-request scan.

!
Off by default, and fail-open

The limit is 0 (disabled) by default because a shared NAT egress aggregates many real visitors behind one address — a mistuned limit locks out a whole office or carrier. It is also deliberately fail-open: under internal state pressure the throttle admits rather than rejects, because failing closed would let a memory bug become an outage. Two Prometheus counters, httpjet_throttle_allowed_total and httpjet_throttle_rejected_total, expose what it is doing. --per-ip-rate overrides the XML value at launch.

GeoIP / ASN rules

Country and network membership come from hj-geo, a root crate with no runtime network access: you point <security><geoipDBFile> at a plain-text CidrList file and refresh it on your own schedule (cron, configuration management — httpjet never fetches). The format is deliberately boring:

geo source file · CidrList format
# country <ISO-3166 alpha-2> <CIDR...>
country US 203.0.113.0/24 198.51.100.0/24
country DE 2001:db8::/32
# asn <number> <CIDR...>
asn 13335 203.0.113.0/24

Ranges load into sorted, merged interval sets queried by binary search — membership is a hot-path O(log n), and an IPv4-mapped IPv6 address is judged in v4 space so a v4 rule can't be dodged by mapping. Semantics: geoDeny/asnDeny are checked first; an allow list with no deny list is a fail-closed whitelist (anything unmatched is refused). Labels resolve once at state build; an unknown label is a hard build error, and check warns when geo directives exist without a geoipDBFile — the ACL would be inert.

!
Geo is as honest as your input

Country labels come from the file you provide; a stale file enforces yesterday's map. And behind a proxy, geo judgments apply to the resolved client IP — see the trusted-proxy rules above.

PROXY protocol trust

A listener with proxyProtocol enabled requires every connection to open with a PROXY v2 (binary) or v1 (text) header carrying the real client address. The header is consumed before the TLS handshake or the H1/h2c sniff, so the claimed address becomes the socket identity for every later stage — ACLs, throttle, logs, PHP's REMOTE_ADDR.

!
The listener opt-in IS the trust decision

Unlike OpenLiteSpeed's server-level trusted-peer ACL, httpjet binds PROXY-protocol trust to the listener itself: every connection to an enabled listener must present a header, and a missing one fails the connection. Enabling it on an internet-facing bind would let anyone forge their client address — check warns on wildcard/public binds for exactly this reason. Point such a listener at your load balancer or local hop only. See Protocol stacks.

HTTP Basic auth

.htaccess can fence a subtree with standard Basic auth — AuthType Basic / AuthName / AuthUserFile plus a Require. The realm is enforced before cache lookup and backend dispatch, so a protected path can't leak through the static fast path or the page cache; valid credentials set REMOTE_USER for PHP. htpasswd supports bcrypt and {SHA} in constant time; apr1/crypt hashes verify false (with a parse-time warning) rather than being weakly accepted. Full semantics live in Rewrite engine.

TLS hardening

The transport security posture (details in Protocol stacks):

  • mTLS — clientVerify 1–3 attaches a webpki client verifier to the listener CA; level 2 requires a client certificate (e.g. Cloudflare origin-pull). Positive chain verdicts are memoized so the verify cost stays off the hot path.
  • Revocation — crlFile adds PEM CRL enforcement to the verifier. Absent means no revocation checking, stated plainly rather than hidden.
  • Cipher discipline — TLS 1.3 offers exactly TLS_AES_128_GCM_SHA256 (the RFC 8446 mandatory suite); TLS 1.2 keeps its full set. Session resumption uses single-use tickets with 0-RTT off, including on client-cert-verifying listeners.
  • One config, two transports — TCP and QUIC share a single rustls::ServerConfig, so a cert, verifier, or CRL change cannot land on one transport and miss the other.

The PHP jail (suEXEC, chroot, namespaces)

When PHP runs, its credential and filesystem isolation resolve through a fail-closed jail: suEXEC (<suexec>, off by default, with uidMin/gidMin floors — uid 0 is always rejected), chroot (chrootMode 0–2), and optional Linux namespaces. A namespace flag that the kernel or build cannot honor is stripped fail-safe — pid is accepted for compatibility but deliberately not honored rather than half-applied. If a configured jail turns out unsafe (root uid, below-floor uid, bad chroot), httpjet disables PHP for that vhost and returns 503 — it never falls back to running the script unjailed, and never falls through to the static handler, which would leak the script source. See LSAPI & PHP.

Request limits & resource fences

The fences that bound any single request's cost:

Audit posture

The August 2026 hardening pass closed 20 confirmed findings from an adversarial self-audit plus 25 internal audit findings — the classes above (fail-closed symlinks and deny-globs, CONTINUATION and stream-id h2 errors, phantom-trailer and FIFO-park fixes, chunked double-charging, generation-file permissions, proxy header-injection stripping) came out of that pass. The posture going forward is the one this page repeats: every new control ships opt-in with a safe default, fails closed when it cannot evaluate, and names its trust decision explicitly.
