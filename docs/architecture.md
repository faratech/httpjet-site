# Architecture

httpjet is a Cargo workspace with **one binary crate** and **nineteen `hj-*` library crates**. Roughly 3,200 test functions span the workspace (3,171 green at v0.2.0).

## Workspace shape

The graph is acyclic and `hj-config` sits at the root. `hj-core` is the small frozen seam for every handler. Two crates, `hj-acme` and `hj-ocsp`, link only behind build features. The binary is the only crate that sees everything. Transports, protocols, gateways and the cache evolve behind `hj-core`. Request-aware page-cache glue also lives in the binary.

One monoio runtime runs per listener fd. It pins to its core when workers equal CPU count. Use `--no-core-pinning` to disable pinning. > [Diagram: transport] One transport, three protocols, one pipeline. Cheap work stays on the monoio core: the H1 codec, the native h2 task, the QUIC driver, and the on-core fast path (finished-response memo, static files, page-cache hits). Anything else crosses uring::bridge into the tokio runtime that owns ServerState, the LSAPI pool, the page cache and reload state, then returns to the monoio core for framing and writes. Bodies ≤ 256 KiB are buffered; larger ones stream on H1, H2 and H3 alike. `--uring-ring coop` is the default since 2026-11-07. It measured +28% RPS and -27% CPU per cookieless H2 cache hit on x86. `legacy` uses flagless rings. `defer` measured ~-2% on the GCE guest. Ring size stays at the default. Ring memory is memlock-charged. Multishot accept is on by default. Use `--no-multishot-accept` for one SQE per connection. Bodies ≤ 256 KiB are buffered. Larger bodies stream on H1, H2 and H3. ## The frozen contract — hj-core This is the seam that lets handlers compose without knowing the transport. Changing these signatures means updating every dependent, so they are treated as frozen: **hj-core** · the seam ``` enum Body { Empty, Full(Bytes), Stream(BoxBody), File(FileBody) } type Request = http::Request ; type Response = http::Response ; // every terminal handler (StaticFiles, Lsapi, FastCgi, ProxyHandler) trait Handler { async fn handle(&self, &mut ReqCtx, Request) -> Result ; } // every post-handler munger (promote → expires → sub_filter → compress → deny-CDN-cache → Alt-Svc) trait ResponseTransform { async fn transform(&self, &ReqCtx, &mut Response); } ``` `FileBody` can pin an open inode across cache swaps. `ReqCtx` carries `server`/`vhost` and client state. It also carries `is_tls`, `protocol` and `trusted_proxy`. Its `env` vec holds rewrite `[E=]` sets and CGI overrides. `Router::resolve(listener, key)` maps SNI/Host to a vhost. i Extending Register new handlers in `pipeline/mod.rs::dispatch()`. Register new transforms in `state.rs::build_transforms`. Out-of-tree code uses the extension registry . ## The request pipeline `pipeline::handle()` is the integration point. It resolves the vhost first. It then applies trust, ACL, geo and throttle checks. It runs optional WAF and extension pre-handlers. It then calls `dispatch()` and applies transforms. It finally writes logs, metrics and spans. `dispatch()` mirrors OpenLiteSpeed ordering. It inserts page-cache seams after rewrite and access resolve. The pinned `LsapiScript` extension keeps the resolved script separate. It pushes `SCRIPT_NAME`/`QUERY_STRING` into `ctx.env` for front controllers. Terminals use an explicit `if/return` chain, not a uniform registry. A failed proxy context falls through to static. A script with no pool **hard-fails 503**. It must never fall through to source. ! Load-bearing detail A rewrite to `index.php` keeps the original `REQUEST_URI`. The cache must key by that original URI. Never key by the rewrite-resolved path. Cache seams stay inert without `--page-cache`. `lscache::cache_lookup` runs before any backend. `lscache::cache_store` runs after `finalize_response`. ## Module organization See the Path note under Crate map . ## Configuration generations Live state publishes as immutable *generations* behind an `ArcSwap`. A SIGHUP or API transaction builds a complete candidate first. It validates the candidate before publishing. In-flight requests finish on their pinned generation. > [Diagram: generations] Candidate → published → retired. A rejected candidate never touches the serving generation. Trust changes (TLS material, mTLS policy, PROXY protocol) retire the old listener group and drain its connections under their pinned policy; boot-owned resources (listener topology, PHP pools, cache stores, privileges) are restart_required. The full ownership inventory and the transactional replacement sequence are on Admin API & reload . ## Code conventions **Formatting:** rustfmt-clean (default settings, edition 2024); `cargo fmt --all --check` is a CI gate.

- **Errors:** `thiserror` types at system boundaries; internal invariant violations panic with a message rather than pretending to recover.

- **unsafe:** Keep `unsafe` rare and never in HPACK. Document the safety invariant above each block.

- **Async:** tokio tasks for independent work, `FuturesUnordered` for multiplexing with coordinated shutdown, no per-stream spawn on hot paths.

- **Hashing:** Use `rustc-hash` only for trusted or hard-capped keys. Limit: the `.htaccess` memo caps at 16 shards × 512 entries, keys ≤ 1 KiB. Untrusted unbounded maps keep SipHash.

- **Allocator:** Use mimalloc globally with threshold-gated trim (`--mimalloc-trim-*`). Limit: production sets `MIMALLOC_PURGE_DELAY=0`, so you pool transient buffers in `hj_core::recycle`.

> [Diagram: recycle-pools] Zero-fault buffer and task recycling (v0.1.2–v0.1.5). Under MIMALLOC_PURGE_DELAY=0, unpooled transient allocations in sparse size classes fault back in on every request. hj_core::recycle pools H2 stream futures, bridge futures, tiered body buffers (frozen into ref-counted Bytes via Bytes::from_owner and returned when the last slice drops), LSAPI read/BEGIN buffers, and per-core 64 KiB TLS record buffers.
