Running it

Configuration & flags

httpjet has two configuration surfaces: the LiteSpeed XML it reads (vhosts, listeners, certs, rewrite, ext-processors) and the CLI flags that tune the runtime (workers, PHP, the page cache, TLS, memory). The XML defines what is served; the flags tune how.

The configuration tree

Point httpjet at a LiteSpeed root with --root (default /usr/local/lsws). It parses conf/httpd_config.xml plus conf/vhosts/*.xml, substituting $SERVER_ROOT and $VH_NAME at parse time, into a normalized model. The file tree is treated as read-only.

LiteSpeed XMLHow httpjet uses it
<listener> + <vhostMap>Bind addresses and the SNI/Host → vhost map (Router::resolve). The map has no cert-name-match, mirroring OpenLiteSpeed.
<virtualHost> docRoot / indexFilesStatic document root and directory-index order (e.g. index.html, index.php).
<vhssl> cert / key / CACertFilePer-vhost TLS material. The vhost CACertFile is server chain material — not a client-verify root; only the listener CA verifies client certs.
<rewrite> + per-dir .htaccessThe rewrite engine: inline rules then the .htaccess chain.
<context> (proxy / script handler)Reverse-proxy contexts and the php/html suffix → LSAPI routing.
ext-processor (LSAPI)The lsphp pool target. The config's LSAPI_CHILDREN=250 is stripped from the spawn env (an OOM hazard) and replaced by --php-children.
fileETag (default 28)The static ETag format — "<size>-<mtime>-<inode>;;;" (note the three trailing semicolons), byte-for-byte LiteSpeed-compatible.
<tuning> request / keep-alive limitsFeeds the shared ServeConfig: connection and header timeouts, request URL/header/body caps, and the H1 maxKeepAliveReq close-after-N-requests cap (0 = unlimited).
<fileAccessControl><followSymbolLink>Folded into each vhost's effective symlink policy.

Subcommands

SubcommandPurpose
serveBind the listeners and serve (the flags below apply here).
checkParse + lint the config without binding ports. check --strict is the deploy gate.
lsphpRun the standalone persistent lsphp "external app" pool that serve --lsphp-external dials — the PHP half of a zero-downtime deploy.

Listeners & workers

FlagDefaultWhat it does
--root <dir>/usr/local/lswsThe LiteSpeed config root to read.
--http-addr <addr>127.0.0.1:8080The HTTP listener bind address (production binds 0.0.0.0:80 through systemd socket activation).
--https-addr <addr>127.0.0.1:4443The HTTPS + HTTP/3 listener. "" disables the TLS/QUIC listener entirely.
--workers <n>CPUsMonoio/io_uring worker count for self-bound listeners, plus the shared tokio pipeline runtime size. Socket-activated production inherits systemd listener fds.
--no-mtlsoffRelax the mandatory Cloudflare client-cert check for local TLS testing (loopback is exempt regardless).
--metrics-addr <addr>127.0.0.1:9090The loopback metrics listener (/metrics, /cache-entries). Empty string disables it; production normally keeps the loopback default.

PHP / LSAPI

FlagDefaultWhat it does
--no-phpoffDon't spawn lsphp; PHP requests fall back to static serving.
--php-socket <path>—httpjet's own lsphp socket. Always use a non-production path for tests.
--php-children <n>—The lsphp worker cap (the config's LSAPI_CHILDREN=250 is stripped regardless).
--lsphp-external <socket>—Dial a persistent lsphp pool run by a separate httpjet lsphp process instead of spawning one. This is the production PHP mode — it lets the web tier restart for a binary deploy without cold-starting PHP. Overrides --php-socket.
!
Sizing PHP

The live config's LSAPI_CHILDREN=250 is a real OOM hazard on a memory-tight box — it's stripped from the spawn env and bounded by --php-children. Profiling shows the pool's acquire latency is ~0–20 µs in production, so it never queues; more children buys nothing.

Page cache

All inert (and ~zero-cost) unless --page-cache is set. The cache is in-RAM by default; the tmpfs file tier is explicit opt-in. See Page cache for what each tier does.

FlagDefaultWhat it does
--page-cacheoffEnable the LSCache-equivalent origin page cache.
--page-cache-mem <bytes>128 MiBRAM budget for the in-process page store: metadata, variants, and in-RAM bodies. With the file tier on, a persisted body is charged metadata-only here.
--page-cache-disk-mem <bytes>2 GiBtmpfs body budget (file tier only) — the second cap, enforced by the store's disk-weight LRU. 0 ⇒ fall back to --page-cache-mem.
--page-cache-store-path <dir>noneThe persistent tmpfs file tier (e.g. /dev/shm/jetcache); default/jetcache selects httpjet's own root. The cache then survives restarts via a boot scan.
--page-cache-hot-mem <bytes>192 MiBThe in-RAM hot tier in front of the file store — hottest bodies serve zero-syscall.
--page-cache-dict <file>—A shared zstd dictionary for internal body dedup (~3.5–9× smaller stored; served bytes stay standard).
--page-cache-admit-threshold <N>2Frequency-sketch store-admission bar — minimum reuse to store (1 = first sight; 2 = second sighting, first possible hit on the third request). Rejects one-hit-wonders.
--page-cache-standard-vhosts <csv>—Vhosts where standard Cache-Control freshness can opt responses into the origin page cache.
--page-cache-privateoffEnable the per-session private tier — logged-in requests route to a per-session key, never the public entries.
--page-cache-private-{session,user}-cookiexf_session / xf_userOverride the session/user cookie names that drive the private tier.
--page-cache-stale-default-secs <N>0Default stale-while-revalidate window when the app declares none.
--page-cache-stale-max-secs <N>86,400Hard cap for stale-while-revalidate windows honored from the app.
--page-cache-stale-if-error-max-secs <N>86,400Hard cap for stale-if-error windows honored from the app.
--page-cache-stale-if-error-default-secs <N>0 (off)A stale-if-error window applied when the app declares none — a backend 5xx serves the retained stale entry instead of the error page.
--page-cache-vary-cookies / --page-cache-private-cookiesXenForo setsComma lists for the public-vary and private cookie sets.
--cache-peer <ip:port>—The other node, for cross-node purge fan-out (active-active coherence). Also gates the loopback purge endpoint.

Compression, memory & egress

Flag (or env)DefaultWhat it does
--cf-send-zstd (or CF_SEND_ZSTD=1)offForce zstd egress to a trusted-proxy (Cloudflare) peer, ignoring the forwarded Accept-Encoding — CF re-encodes per browser at its edge. Never affects direct clients. Production enables this with the cf-send-zstd.conf systemd drop-in on both nodes. See Compression.

--profile-token <token>disabledOptional token for the loopback-only profiling endpoint when the binary is built with profiling support.
