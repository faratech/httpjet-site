Release sweep 2026-11-08 — raw logs and checks

Every release from v0.0.1 to v0.1.12, measured under identical conditions on a dedicated lab VM (Google Cloud c4-highmem-8, Ubuntu 26.10 — the production x86 origin's machine type). No production host was loaded: server and load generator both ran inside the VM, over its loopback, server pinned to cores 0-3 (--workers 4), h2load to cores 4-7. Each release was PGO-built from its tag with one unified gather profile (Rust 1.99.1) and served with uniform production flags. Three rounds per build in rotated order; tables show medians. Per-round data: release-sweep-2026-11-08.tsv.

Workloads: static = 1 KiB file (h2 c=32 m=10 / h1 c=100); empty = 0-byte file (h2); big = 64 KiB file (h2, n=20k); heavy = /robots.txt through the real 806-line forum .htaccess chain; php = bench.php?n=50 over the real lsphp (h1 c=40); cache = 37 KB PHP fixture page (cachebench.php) through the real origin page cache (h2 c=32 m=32) — the lab has no XenForo database, so the cache workload is a fixture, not a forum page. PHP for v0.0.1–v0.0.3 measures cold-pool ramp: those builds grow their lsphp pool slowly from cold (single request ~3 ms; warm pool ~32k req/s on v0.0.1 — see extended/php-warm-v0.0.1.log). TLS used a lab self-signed RSA-2048 certificate; heavy H2 is connection-bound on it (~110k for every build), so read its H1 line for trend.
