LSAPI & PHP

httpjet speaks the native LSAPI wire protocol to an operator-configured lsphp executable — no FastCGI shim or translation layer. The hj-lsapi crate holds the wire codec, a UDS client pool, the lsphp process supervisor, the CGI environment builder, and a security-critical jail.

Overview

When dispatch routes a request to a configured PHP suffix, httpjet talks LSAPI directly to lsphp. Everything PHP-facing lives in hj-lsapi, split into five concerns: the wire codec, the UDS client pool, the process supervisor, the CGI environment builder, and a fail-closed jail. PHP is optional; static and proxy deployments do not need an LSAPI executable.

The LSAPI wire codec

proto.rs implements the protocol straight from the vendored php-src lsapidef.h constants — the codec builds and parses LSAPI frames directly, with no intermediate FastCGI representation. The shape of the BEGIN_REQUEST frame carries one sharp edge worth stating precisely.

Every env key and value (and every known header value) is length-prefixed with a big-endian u16 that includes the trailing NUL. That single byte of overhead sets a hard ceiling: the largest safe field length is u16::MAX - 1. A longer field would make the NUL-inclusive prefix wrap, and a wrapped length desyncs lsphp's parser — every subsequent frame is then misread.

proto.rs · the NUL-inclusive length prefix
// each env/header field is written as:
//   [u16 BE = byte_len + 1] [bytes...] [0x00]
// the prefix counts the trailing NUL, so:
const MAX_FIELD: usize = (u16::MAX as usize) - 1; // 65534 bytes
// a field of u16::MAX or more would wrap len+1 → parser desync

The codec is transcribed from the upstream php-src litespeed SAPI sources (BSD-3-Clause, vendored under the crate), so the wire format matches byte-for-byte what lsphp expects to read.

The UDS connection pool

Requests reach lsphp over a Unix-domain socket. The pool that fronts it carries a generation-epoch plus an idempotent retry: when a worker is recycled out from under an in-flight request, the stale connection is detected and the request is retried on a fresh one rather than served a poisoned response. The epoch is what lets the pool tell "this socket belongs to the worker generation I dialed" from "this socket outlived a recycle."

Two failure modes are handled explicitly. A bodyless idempotent request whose pooled connection dies before the send gets one transparent retry on a fresh connection, bounded by the processor's retryTimeout; the retry dials fresh rather than reusing another pooled entry. And accepted connections keep TCP keepalive — a vanished WebSocket or proxy client no longer pins fds and pool permits indefinitely.

i
Why a generation epoch

An opcache recycle or a child churn tears down sockets mid-flight. Without the epoch, a retry could land back on the same dying connection. The epoch tags each pooled connection with the generation it was opened against; a recycle bumps the epoch, and the idempotent retry only re-dials a connection from the current generation.

The lsphp supervisor

In its self-managing mode, hj-lsapi spawns and supervises lsphp itself. The supervisor passes the listen socket to the child on fd 0 (where lsphp expects its LSAPI listener), sets PR_SET_PDEATHSIG so a worker dies with its parent rather than orphaning, and caps the child count. The pre_exec closure that runs between fork and exec calls only async-signal-safe syscalls — the one regime where almost everything else is undefined behavior.

Pool sizing comes from the config's maxConns (or the PHP_LSAPI_CHILDREN env the worker sees) and can be overridden with --php-children; values below 2 normalize to 2. Treat that count as a memory-capacity decision for the deployment, not a throughput target to maximize blindly.

!
Packaging boundary

httpjet does not ship a PHP runtime. The PHP executable, its extensions, php.ini, and writable application paths are explicit operator-managed dependencies.

Zero-downtime deploys (the external pool)

The supervisor mode above couples PHP's lifetime to httpjet's: restarting the server cold-starts workers. The httpjet lsphp subcommand instead runs a persistent lsphp pool as its own systemd unit (httpjet-lsphp.service, Type=notify); the web tier then dials that pool with serve --lsphp-external <socket> and never spawns workers itself.

The payoff is a zero-downtime deploy on both halves: the web tier can systemctl restart httpjet for a fresh build without cold-starting PHP, and an opcache recycle replaces the pool's worker generation — via httpjet lsphp-reload or a pool-unit restart — without closing the systemd-owned LSAPI listener, so the web tier's pooled connections drain onto the new generation instead of erroring.

production · external pool wiring
# the PHP half: a persistent pool under its own identity (its own unit)
httpjet lsphp --php-socket /run/httpjet/php.sock \
  --control-socket /run/httpjet/lsphp-control.sock \
  --generation-file /run/httpjet/lsphp.generation

# the serving half: dial that pool, never spawn — restart freely
httpjet serve --lsphp-external /run/httpjet/php.sock \
  --lsphp-generation-file /run/httpjet/lsphp.generation
!
The generation file is the trust anchor

The 16-byte generation epoch is how a web tier tells its pool from a foreign one — advancing the wrong marker would drop the live web tier's pooled connections and retire its workers against a file it never wrote. The generation file's parent directory must not be group- or other-writable, and an external pool requires the flag to be present-and-openable. Test pools default their control and generation sockets beside the test pool socket so they can never touch the production epoch.

i
Separate trust domain

The supplied pool unit uses a distinct httpjet-php identity. Do not grant it access to web-tier TLS keys or purge secrets.

The CGI environment

The env builder assembles the CGI/LSAPI environment for each request. The load-bearing piece is the split between what was requested and what runs: a LsapiScript request-extension pins a resolved SCRIPT_FILENAME while keeping the original REQUEST_URI, with SCRIPT_NAME and QUERY_STRING pushed into ctx.env — which the env builder upserts over its defaults.

That separation is exactly what makes XenForo-style front-controller routing correct: a rewrite to index.php resolves the script to run without losing the real request URI the application reads back. (It is also why the page cache must key by the original URI — see the rewrite engine for the routing side.)

.htaccess php_value / php_admin_value directives are honored too, carried through the LSAPI special-env section with the right user-vs-admin permission level. Plain lsphp ignores a regular CGI PHP_VALUE, so these overrides only take effect because httpjet emits them on the special-env wire path rather than as ordinary env entries.

The jail

PHP execution is fenced by a config-gated jail — suEXEC, chroot, and namespace isolation. The jail is fail-closed, and the resolution has two distinct outcomes worth separating.

When suEXEC is off, the process is non-root, or the vhost asks for no per-vhost isolation, the jail resolves to the all-None case and collapses to the default "php" pool — single-pool behavior preserved byte-for-byte, no surprises. But when a jail is configured and turns out unsafe — a root uid, a uid below the floor, a bad chroot — httpjet disables PHP for that vhost and returns 503. It never runs as root, and it never silently falls back to running the script unjailed.

!
Source-disclosure guard

A script that resolves to a PHP handler must be identified as PHP even when the pool is unavailable. If the request fell through to the static handler instead, the server would hand back the raw .php source. So an unavailable pool returns 503 — it must never fall through to static and leak the script.

Request bodies

On the chunked / no-Content-Length path, LSAPI needs a concrete m_reqBodyLen before the body can be sent — so httpjet must know the full length first. collect_to_cap drains the request body for that case while enforcing max_body as frames arrive: the moment the accumulated size would exceed the cap, it returns PayloadTooLarge rather than buffering an unbounded body to discover the length.

handler.rs · cap enforced per frame
while let Some(frame) = body.frame().await? {
    if let Some(data) = frame.data_ref() {
        if (buf.len() as u64) + (data.len() as u64) > max_body {
            return Err(HandlerError::PayloadTooLarge); // the instant the cap is crossed
        }
        buf.extend_from_slice(data);
    }
}
