Docs/CLI reference

Running it

CLI reference

One binary, four subcommands. --root is the only global option. Persistent policy lives in the XML; everything on the command line is an operational override — addresses, workers, PHP wiring, cache budgets, feature opt-ins. This page is generated from httpjet serve --help of v0.1.5 plus the feature-gated flags.

Subcommands

httpjet [--root DIR] <subcommand>
httpjet --root /abs/root check [--strict]     # parse + summary; --strict lints topology and exits non-zero on findings (deploy gate)
httpjet --root /abs/root serve [flags…]       # bind the configured listeners and serve
httpjet --root /abs/root lsphp [flags…]       # run a standalone persistent lsphp pool (the PHP half of a zero-downtime deploy)
httpjet lsphp-reload [flags…]                 # ask a running pool to replace its worker generation without closing the listener
httpjet --version                             # httpjet 0.1.5

--no-mtlsoffLocal testing / explicit rollback only: drop the mandatory Cloudflare client-cert requirement so TLS content can be tested locally without a Cloudflare-issued client cert. Without this flag, clientVerify=2 validates every presented certificate during TLS. A peer that presents none completes the handshake, then the request pipeline rejects it before dispatch (except the loopback exemption)
--per-ip-rate <PER_IP_RATE>—Per-client-IP request throttle: max requests per client IP per second. 0 (default) = disabled — overrides the <perIpRate> tuning field when set. Protects the origin from single-source floods; a shared NAT egress aggregates many visitors, so size accordingly
--request-decompression-extra <REQUEST_DECOMPRESSION_EXTRA>(empty)Additional request Content-Encoding values to decode before dispatch. Gzip remains enabled for compatibility; Brotli and zstd are opt-in. Accepted comma-separated values: br,zstd
--trusted-proxy-idle-secs <SECS>0Idle window in seconds for connections whose peer presented a VERIFIED client certificate (in prod, only Cloudflare's authenticated-origin-pull cert). CF never resumes TLS to the origin, so closing a connection it would have reused costs a full TCP + TLS + mTLS handshake. 0 keeps the normal 90 s floor for everyone; uncertified peers always keep it
--trusted-proxy-idle-max-conns <MAX_CONNS>6000Above this many open connections, certified connections fall back to the normal idle floor (bounds idle state during a connection surge)

Page cache
--page-cacheoffEnable the LSCache-equivalent origin full-page cache (OFF by default; opt-in / R&D). Per-vhost <cache><enableCache> + .htaccess CacheLookup still gate each request, and the app must opt responses in via X-LiteSpeed-Cache-Control. With this flag absent the cache is inert
--page-cache-mem <MEM>134217728RAM budget (bytes) for the in-process index: entry metadata + precompressed variants + any in-RAM body. With --page-cache-store-path, persisted (tmpfs) bodies do NOT count here — they are bounded by --page-cache-disk-mem instead — so this should be sized for metadata, not body bytes. Without a file tier it is the whole body budget, as before. Default 128 MiB
--page-cache-disk-mem <DISK_MEM>2147483648tmpfs file-tier footprint budget (bytes) for --page-cache-store-path: the disk LRU evicts the least-recently-served entry once charged file footprint under the store path exceeds this. tmpfs IS RAM, so size it against the box's headroom (with dict compression a 2 GiB cap holds the compressed equivalent of ~7–18 GiB of pages). 0 ⇒ fall back to --page-cache-mem. Ignored without a file tier. Default 2 GiB
--page-cache-store-path <STORE_PATH>noneDirectory for the PERSISTENT tmpfs file tier. The default is "none": bodies stay in the in-process RAM cache and flush on restart. Pass an explicit directory such as /dev/shm/jetcache to opt into the LiteSpeed-Enterprise-style store where bodies live as files and the cache survives restarts via a boot-time warm scan. The LiteSpeed config's cacheStorePath is intentionally NOT used
--page-cache-integrity-key <INTEGRITY_KEY>/usr/local/httpjet/conf/.jetcache.keyIntegrity key used for persistent cache containers
--page-cache-integrity-requiredoffRefuse to start the file tier when the integrity key cannot be installed, instead of running with untagged containers
--page-cache-hot-mem <HOT_MEM>201326592Byte cap of the in-RAM hot tier in front of the file store (zero-syscall zero-copy serves for the hottest bodies). Only meaningful with --page-cache-store-path. Default 192 MiB
--page-cache-dict <DICT>(empty)Path to a shared zstd dictionary used to store cached bodies far smaller. CMS pages share ~60%+ of their bytes as position-shifted boilerplate that only a dictionary captures; with this set, cache_store dict-compresses the stored body (the SERVED bytes stay standard zstd/br/gzip — browsers/CF can't decode a private dict). Absent/empty/unreadable ⇒ bodies are stored as plain identity (today's behaviour). Build one from a reviewed local corpus with scripts/train-pagecache-dict-from-files.sh
--page-cache-dict-vhost <DICT_VHOST>(empty)Comma-separated vhost=path pairs: a PER-VHOST zstd dictionary, trained on that vhost's own content (train one local corpus per vhost). A shared dictionary trained on one site's boilerplate does little for a differently templated site, so each vhost compresses against its own. A vhost not listed here falls back to --page-cache-dict if set, else stores identity (today's behaviour). Example: forum.example=conf/pagecache-forum.dict,moon.example=conf/pagecache-moon.dict
--page-cache-dict-level <DICT_LEVEL>(empty)Comma-separated vhost=level pairs overriding the internal zstd level (1-19, default 12) of that vhost's dictionary. A vhost whose compressed bodies round to the same 4 KiB tmpfs pages at a cheaper level gains nothing from 12 (one production vhost costs 5× less at level 3 with no footprint change). A malformed pair aborts startup
--page-cache-vary-default <VARY_DEFAULTS>(empty)Comma-separated name=value pairs: a vary cookie carrying this value is keyed like no cookie (the app treats the default the same way). E.g. xf_style_id=50
--page-cache-opt-in-status <OPT_IN_STATUS>(empty)Comma-separated extra statuses (from 303, 404, 410) cached only when the app sends an explicit X-LiteSpeed-Cache-Control: public, with the TTL capped at 300 s and no stale windows. Empty = off (only 200/301 are cached)
--page-cache-303-prefixes <PREFIXES>(empty)Comma-separated request-path prefixes under which an opted-in 303 may be stored (e.g. /whats-new/). A 303 anywhere else is never stored
--page-cache-stream-fill-vhosts <VHOSTS>(empty)Comma-separated vhost names whose cacheable page-cache misses WITHOUT a Content-Length (progressive template output) are sent to the client as the backend writes them and stored once the backend finishes, instead of being buffered whole first. Only identity-encoded public 200s; a body that errors, is cut short or grows past the object cap is served but never stored. Empty = off
--page-cache-admit-threshold <ADMIT_THRESHOLD>2(W-TinyLFU) Base admission bar: minimum frequency a cacheable response must show before it is STORED. One request counts as ONE sighting — the on-core fast path probes uncounted and records only a hit it serves. 2 = store on the 2nd sighting (miss-miss-hit; rejects the long-tail of one-hit-wonders — the default). 1 = store on the 1st sighting (miss-hit; cache everything — now cheap with --page-cache-dict, with the store's byte LRU protecting the hot set). Size-weighting adds +1 per 256 KiB on top. Watch httpjet_cache_hit_ratio_real to tune
--page-cache-vary-cookies <VARY_COOKIES>xf_style_variation,xf_style_id,xf_language_idComma-separated public-vary cookie names: a cacheable public response may declare X-LiteSpeed-Vary: cookie=NAME,... and the entry is keyed by these cookies' values (shared, non-sensitive prefs). Default matches the XenForo style/language set
--page-cache-private-cookies <PRIVATE_COOKIES>xf_session,xf_userComma-separated cookie names that forbid public caching if a public response tries to Set-Cookie them (session guard). Default: XenForo
--page-cache-privateoffEnable the per-session PRIVATE cache tier: an X-LiteSpeed-Cache-Control: private[,max-age=N] response from a logged-in request is stored keyed by the session cookie and served only to that same session. OFF by default — without the flag a private opt-in bypasses exactly as before
--page-cache-private-session-cookie <PRIVATE_SESSION_COOKIE>xf_sessionRequest cookie whose VALUE keys a private entry's owner (the session)
--page-cache-private-user-cookie <PRIVATE_USER_COOKIE>xf_userRequest cookie whose PRESENCE routes a request to the private tier (the logged-in marker; XenForo's remember cookie)
--page-cache-shared-paths <SHARED_PATHS>(empty)Comma-separated matchers for visitor-invariant endpoints that MEMBER (logged-in) requests may still read/populate on the PUBLIC cache tier — sharing one entry across guests and every member session instead of duplicating per session and re-rendering each member's first view through PHP. Two matcher forms: PATH?PARAM (path equals PATH exactly AND the query carries PARAM=, e.g. proxy.php?image) and PATH (path prefix, e.g. /wf-unfurl/image); a missing leading / is normalized on. ONLY list endpoints whose bytes are identical for every visitor (HMAC-gated image proxies) — never HTML pages. Malformed specs abort startup. Empty/absent = feature inert (kill switch; members keep today's private routing). GLOBAL like the other --page-cache-private-* knobs — not per-vhost — but a matching request still passes every per-vhost public gate (vhost cache policy, .htaccess CacheLookup) and every public-store guard before it is served or stored
--page-cache-shared-paths-canary-percent <SHARED_PATHS_CANARY_PERCENT>100Deterministic percentage (0-100) of member requests matching --page-cache-shared-paths that actually route to the public tier; the rest keep today's private-tier behavior. --page-cache-standard-vhosts <STANDARD_VHOSTS>(empty)Comma-separated vhost names put into "standards mode": they honor a standard Cache-Control: public, max-age=N as a cache opt-in (OpenLiteSpeed's checkPublicCache equivalent), get a default public cache policy when they declare no <cache> block, and default CacheLookup to on — so a non-LiteSpeed app (e.g. moon.example) caches like a standards-compliant shared cache. ALLOWLIST, not a global switch: a vhost not listed is unaffected (X-LiteSpeed opt-in only), so opting one content site in can't make an unrelated vhost (status/admin API) cache a response it merely marked public. All other guards (GET-only, Set-Cookie/private-cookie, vary, status, self-redirect) always apply

Performance knobs
--no-fast-memooffDisable the finished-response memo on the on-core static fast path (default ON; per-thread, 1 s TTL, byte-identity-gated — see pipeline::fast_memo). Env HJ_FAST_MEMO=0 is equivalent
--cf-send-zstdoffCompress responses to a trusted-proxy (Cloudflare) peer as zstd, ignoring the forwarded Accept-Encoding. CF asks the origin for br/gzip but decodes an origin Content-Encoding: zstd and re-encodes per browser at its edge — so this hands CF the cheapest-to-produce form (zstd ≪ brotli to compress) without changing what browsers receive. Officially unsupported CF↔origin; opt-in, default off. Never applies to untrusted (direct) clients. Off ⇒ byte-identical to today
--rewrite-outcome-ttl-ms <REWRITE_OUTCOME_TTL_MS>1000TTL in milliseconds for the rewrite-outcome cache (memoized rewrite decisions for path_cacheable chains, keyed by vhost/scheme/ method/host/path/query + any keyable header vars). 0 disables the cache entirely. The default (1000 ms) matches the historical hard-coded TTL — it bounds -f/-d filesystem staleness exactly like the StatCache and lets .htaccess edits take effect within ~1 s
--rewrite-ua-classifyoffKey UA-reading rewrite chains by the bitmap of matching User-Agent RewriteConds instead of the raw UA string, when parse-time analysis proves the outcome depends on the UA only through those match results. Collapses real-world UA diversity (near-zero hit rate on raw UAs) onto a handful of outcome-cache entries. Default OFF — enabling is a deploy-time decision

Removed flags

--cache-peer / --cache-peer-fill* (cross-node cache peers) and --cache-purge-secret-file are gone; the purge endpoint is loopback-gated. --io-uring / --io-uring-h3 never existed as opt-ins — the io_uring transport is unconditional.

Exit behavior and signals

SIGHUP
Reload configuration and certificates through the publication coordinator; a bad config keeps the current generation (see Admin API & reload).
SIGTERM / SIGINT
Graceful shutdown: stop accepting, GOAWAY h2, drain within the unit's TimeoutStopSec, close the admin coordinator, flush logs and telemetry, bounded OTel shutdown.
Argument validation
Public admin binds, missing companion options (--admin-token-file, --admin-resource-root, ACME requirements), malformed --page-cache-shared-paths or --page-cache-vary-default / --page-cache-dict-level pairs, an unopenable generation file, or a rejected WAF configuration fail startup before any socket is bound; --page-cache-integrity-required additionally refuses to start the file tier when the integrity key cannot be installed.
Socket activation
Inherited fds are adopted by address/path; their count must match --workers for TCP listeners.
