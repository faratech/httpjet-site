What httpjet is

httpjet is a full origin server on a memory-safe, observable Rust core, built to replace LiteSpeed Web Server (LSWS 6.3.5 compatibility target) without a configuration migration: point --root at the existing tree and go.

  • Reads the LiteSpeed-compatible XML tree — conf/httpd_config.xml, per-vhost files, mime.properties — with faithful value semantics, plus opt-in httpjet-native extensions (throttling, geo/ASN ACLs, PROXY protocol, sub_filter, context overrides).
  • Speaks the native LSAPI wire protocol to a configured lsphp executable (no FastCGI shim), with a zero-downtime external pool and a fail-closed jail.
  • Evaluates the same .htaccess rewrite rules, access control, Basic auth, and header directives.
  • Serves HTTP/1.1, a from-scratch HTTP/2 stack, and HTTP/3 over QUIC, with optional client-certificate verification.
  • Provides an opt-in origin page cache speaking the LSCache protocol (X-LiteSpeed-* headers), so tuned applications need no changes.
  • Enforces hardened access control: trusted-proxy client-IP resolution, per-client-IP throttling, offline GeoIP/ASN rules, PROXY protocol, and revocation-aware mTLS.

Public beta preparation

The source tree includes a working example configuration and generic systemd units. Signed public binary packages, installer UX, and a supported-platform matrix are the next release work; see Operations.

Why it exists

LiteSpeed is fast, but it is closed source. httpjet exists to put the same deployment model — the same XML, the same .htaccess semantics, the same LSCache protocol — on a memory-safe core the operator can read, extend, and instrument. Compatibility is the feature: an existing LiteSpeed tree is a working httpjet configuration on day one, and the opt-in httpjet-native extensions layer new capabilities on top without forking the format.
