httpjet

A from-scratch async Rust web server, built as a drop-in replacement for LiteSpeed. It reads the same LiteSpeed XML config, speaks native LSAPI to the same lsphp, runs the same .htaccess rules, and ships an LSCache-equivalent origin page cache. Two nodes serve production behind Cloudflare.

What httpjet is

httpjet reimplements the parts of LiteSpeed Web Server (LSWS 6.3.5) that matter for a real deployment, on a memory-safe, observable Rust core. It is not a config translator or a proxy in front of LiteSpeed — it is a full origin server that consumes LiteSpeed's own configuration and protocols directly:

  • Parses the same httpd_config.xml + per-vhost XML — the two servers are interchangeable for cutover and rollback.
  • Speaks the native LSAPI wire protocol to the same lsphp binary (no FastCGI shim).
  • Evaluates the same .htaccess rewrite rules, access control, and header directives.
  • Serves HTTP/1.1, a from-scratch HTTP/2 stack, and HTTP/3 over QUIC, with Cloudflare-style mutual TLS.
  • Provides an LSCache-equivalent origin page cache driven by the same X-LiteSpeed-* headers the application already emits.
i
In production

There is no LiteSpeed serving anymore. httpjet runs on :80/:443 as an active-active pair (x86-64 + aarch64) behind Cloudflare, systemd-managed and monit-watched, with the origin page cache live.

Why it exists

LiteSpeed is fast and feature-rich, but closed and license-gated. httpjet reproduces the behavior a production site actually depends on — the config surface, LSAPI, .htaccess, TLS, and the cache — while keeping the core open, memory-safe, and deeply observable. Because it reuses LiteSpeed's configuration verbatim, adopting it was a cutover, not a migration: the same config file boots either server, so rollback was always one restart away.
