Running it

Operations & deployment

httpjet is designed for a conventional Linux service deployment: a dedicated account, strict native TOML, systemd hardening, and an explicit separation between the web tier, an optional PHP pool, and application-specific integrations. The checked-in units are generic references, not a copy of any live environment.

Installation status

Public signed binary packages and an installer are not published yet. Today, build from source and follow the included systemd reference. Do not treat internal build, benchmark, or deployment scripts as a public installation path.

source install · native static site
cargo build --release -p httpjet
sudo useradd --system --home-dir /var/lib/httpjet --no-create-home \
  --shell /usr/sbin/nologin httpjet
sudo install -m0755 target/release/httpjet /usr/bin/httpjet
sudo install -d -o root -g httpjet -m0750 /etc/httpjet /etc/httpjet/vhosts
sudo install -o root -g httpjet -m0640 examples/httpjet.toml /etc/httpjet/httpjet.toml
sudo install -o root -g httpjet -m0640 examples/vhosts/example.toml /etc/httpjet/vhosts/example.toml
sudo install -m0644 systemd/httpjet.service /etc/systemd/system/httpjet.service
sudo /usr/bin/httpjet --config /etc/httpjet/httpjet.toml check --strict
sudo systemctl daemon-reload
sudo systemctl enable --now httpjet
!
Review before start

The example binds loopback :8080 and uses an example document root. Set the listener, domains, document roots, TLS material, and writable application paths deliberately before enabling a public service.

Systemd model

The reference httpjet.service runs /usr/bin/httpjet --config /etc/httpjet/httpjet.toml serve as the dedicated httpjet account. It grants only CAP_NET_BIND_SERVICE, makes the filesystem read-only except for systemd-managed runtime/state/cache/log directories, and keeps policy in TOML instead of ExecStart flags.

Socket activation is optional. The base service self-binds native listeners; install httpjet.socket only after making every socket address match TOML. Use the service manager for lifecycle operations—never broad process-kill patterns.

Safe change workflow

  1. Edit selected TOML or application content in a reviewable change.
  2. Run httpjet --config … check --strict as the eventual service identity.
  3. Test with isolated listeners, a separate PHP socket, and a separate cache root.
  4. Restart through systemd for listener, TLS-binding, PHP-pool, cache-runtime, or binary changes. Use reload only for documented soft configuration changes.
  5. Probe the origin directly and check service logs; purge any outer cache if an incorrect cacheable response reached it.

Keep installed binaries outside Cargo's target/ directory. A source build or cargo clean must never remove the binary a running unit depends on.

Optional persistent PHP pool

Static and reverse-proxy deployments need no PHP. For LSAPI, the supplied httpjet-lsphp.socket and httpjet-lsphp.service units run a separate pool under the httpjet-php account. Set the web configuration's runtime.php.external_socket and the pool configuration's runtime.php.socket to the same Unix socket.

This lets the web service restart without cold-starting PHP while keeping PHP configuration and application secrets separate from TLS and cluster secrets. The operator still supplies the LSAPI-capable lsphp executable; httpjet does not install LiteSpeed or PHP packages.

Cache safety and observability

The page cache is off by default. Before enabling it, prove the application has explicit cache headers and exercise URL, host, scheme, cookie/private-tier, purge, persistence, and peer-auth behavior that applies to that application. A cache bug may be retained by an outer CDN after the origin is repaired.

inspect a configured cache
# metrics remain on the configured, normally loopback-only address
curl -s http://127.0.0.1:9090/cache-entries

# native applications expose X-HttpJet-Cache and standard Cache-Status
curl -I -H 'Host: example.test' http://127.0.0.1:8080/ | grep -Ei 'x-httpjet-cache|cache-status'

# loopback tag purge; configured peers also need HMAC authentication
curl -s -X POST -H 'x-httpjet-purge: tag=example' \
  -o /dev/null -w '%{http_code}\n' http://127.0.0.1/__hj_cache_purge

/cache-entries reports hits, misses, stores, purges, file-tier errors, and byte budgets. Judge cache health by those counters and direct content checks, not a transient raw file count.

Release and upgrade discipline

A public release must provide portable x86_64 and aarch64 artifacts, checksums, signatures or attestations, an SBOM, a license, and a documented Linux/kernel/libc support floor. Existing architecture-tuned PGO and cross-build helpers are deployment-specific and must not be uploaded as generic binaries.

Package upgrades should preserve /etc/httpjet, dictionaries, and state; stage and validate a new binary before restart; and retain a known-good binary for rollback. Dictionary rotation is deliberate: write the new file atomically, validate its configuration, restart the service, and expect old dictionary-generation cache entries to become safe misses.
