Quickstart

httpjet is a drop-in replacement for LiteSpeed Web Server: it reads the same conf/httpd_config.xml tree your existing deployment already uses. This walks from a source checkout to a running origin using the checked-in example tree — build the binary, validate the configuration, and serve. No migration step exists because there is nothing to migrate.

Prerequisites

  • Linux with usable io_uring support, plus a C toolchain for the crypto and allocator dependencies.
  • Rust 1.97 or newer (the workspace MSRV; edition 2024). Public binary packages are being prepared; until then, build from the checkout.
  • Only for PHP: an LSAPI-capable lsphp executable supplied by the operator. Static and reverse-proxy deployments do not need PHP or a LiteSpeed installation.
i
Release status

The repository does not yet publish signed installable binaries or distribution packages. Treat this guide as the source-install path; do not use deployment-specific scripts as a general installer.

Build the binary

A debug build is fine for iteration. Use a normal release build for local serving and reproducible tests. The checked-in PGO helper (scripts/build-pgo.sh) is tailored to one deployment and is not a general release-build command.

build · cargo
# debug build — fast to compile, ~5x slower at runtime
cargo build -p httpjet

# release build (REQUIRED for any benchmarking)
cargo build --release -p httpjet  # → target/release/httpjet

The workspace is large (1 binary + 15 hj-* libraries), so when iterating on one crate, scope the build and tests with -p, e.g. cargo test -p hj-rewrite.

Point it at a configuration tree and validate it

httpjet is configured by a server root directory containing conf/httpd_config.xml, an optional conf/mime.properties, and the per-vhost XML files it references — the same layout LiteSpeed uses. The checked-in examples/litespeed/ tree is a minimal working example: one plain listener on 127.0.0.1:8080, one static vhost (example.test) with PHP and symlinks disabled.

check · config lint
printf 'hello from httpjet\n' > examples/litespeed/example/public/index.html

# parse the tree and print a summary (the default subcommand is `check`):
./target/debug/httpjet --root "$PWD/examples/litespeed" check

# strict mode additionally lints the vhost/listener topology and exits
# non-zero on findings: a docroot shared by two vhosts, an apex domain
# mapped without its www. twin, a vhost with no exact vhostMap domain.
./target/release/httpjet --root "$PWD/examples/litespeed" check --strict

Paths inside the XML are resolved against the substitution variables $SERVER_ROOT, $VH_ROOT, $VH_NAME and $HOSTNAME — so the example tree works from any checkout location. See Configuration for the full directive reference.

Run it — for development

The example is HTTP-only on 127.0.0.1:8080 with PHP and the page cache disabled, so it is safe to run alongside an existing server. Runtime behavior is controlled by explicit serve flags (the XML holds persistent policy; the flags hold operational overrides).

serve · dev (alt ports)
./target/release/httpjet --root "$PWD/examples/litespeed" serve \
  --http-addr 127.0.0.1:8080 --https-addr "" \
  --workers 1 --no-php
!
Keep test state isolated

Use alternate HTTP/HTTPS/metrics ports, a separate PHP socket if PHP is enabled, and a separate page-cache store path. Do not bind a test instance to a service manager's production listeners. Test lsphp pools also default their control and generation sockets beside the test pool socket, so they can never touch the production epoch.

Verify

Fetch the example page. The page cache is off by default; when you later enable it (--page-cache), applications opt in with the LiteSpeed cache protocol (X-LiteSpeed-Cache-Control, X-LiteSpeed-Tag, X-LiteSpeed-Vary) — the same headers LSCache already speaks.

verify · curl
curl -i -H 'Host: example.test' http://127.0.0.1:8080/

# after enabling a cacheable application response, inspect:
curl -I -H 'Host: example.test' http://127.0.0.1:8080/ | grep -Ei 'x-litespeed-cache|cache-status'
